本文件定义仓库内 Markdown 文档的通用写作、排版与链接规范，用于保证不同阅读器和 Obsidian 中的基础可读性。

---

## 1 基本排版

- Markdown 文档不使用一级标题，文档开头不写 `# 标题`。
- 中文与英文、数字、符号之间保留必要空格。
- 标题编号应连续，且与层级对应。
- 列表缩进、表格对齐、强调方式保持一致。
- 总览性质或对比性质的表格优先放在文章前部。
- 不使用 HTML 作为排版手段。

---

## 2 标题结构

- 顶层正文标题从 `## 1 标题` 开始。
- 下一级标题使用 `### 1.1 标题`。
- 再下一级标题使用 `#### 1.1.1 标题`。
- 同一层级标题编号应连续，不跳号。

---

## 3 链接规范

### 3.1 普通文件链接

同仓库内文件链接优先使用相对路径：

```md
[显示文字](../path/to/file.md)
```

路径中有空格时，使用 `%20` 编码：

```md
[显示文字](../path/to/file%20name.md)
```

### 3.2 文内标题跳转链接

同一文档内跳转到标题时，使用标准 Markdown 链接，目标写完整标题文本，并将标题中的空格编码为 `%20`：

```md
[显示文字](#2.1%20标题文本)
```

对应标题：

```md
### 2.1 标题文本
```

不要使用以下写法作为通用文内跳转：

```md
[[#2.1 标题文本|显示文字]]
```

```md
[显示文字](#custom-anchor)
<a id="custom-anchor"></a>
```

原因是 Obsidian、Typora 和其他 Markdown 阅读器对 Wiki 链接、自定义 HTML 锚点和中文 slug 的处理不完全一致；直接指向真实标题文本并编码空格，是当前仓库验证可用的写法。

### 3.3 跨文件标题跳转链接

跨文件跳转到某个标题时，使用相对文件路径加标题锚点：

```md
[显示文字](file.md#2.1%20标题文本)
```

若路径包含空格，文件路径中的空格也使用 `%20` 编码：

```md
[显示文字](../folder/file%20name.md#2.1%20标题文本)
```

---

## 4 数学与代码

- 行内数学表达式使用 `$...$`。
- 独立数学表达式使用 `$$...$$`。
- 代码块使用标准 fenced code block，并尽量标注语言。
- 不为排版目的插入 HTML。
